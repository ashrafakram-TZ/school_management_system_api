School API Architecture

How the Tamilzorous School Management backend is built: one NestJS 10 modular monolith with one PostgreSQL database. It serves the Admin web and the Flutter app (Staff, Parent and Driver). Bus tracking lives in the separate Telematics service, which this API only reads from.

2System context

Three clients, one API, one database. External services sit behind small clients, and each has an .env switch so local runs need none of them.

Boundary: no MQTT, device or telemetry tables here. Bus data comes only through modules/fleet/telematics.client.ts (TELEMATICS_API_URL, TELEMATICS_API_KEY).

6Data model rules

Base entities

BaseEntity (integer id, created_at, updated_at), TrackedEntity (+ created_by, filled by CreatedBySubscriber), SchoolScopedEntity (+ school_id).

Naming and time

snake_case for every column, DTO field and JSON key. All times are timestamptz, shown in APP_TIMEZONE (+05:30).

People are never hard-deleted

No cascade delete on users, students, staff or guardians. Soft delete only.

Encrypted fields

Staff bank account and PAN use FieldCipher (AES-256-GCM, DATA_ENCRYPTION_KEY), with only the last 4 digits in clear. Central Auth tokens on sessions are encrypted the same way.

Signed QR

ID cards carry TZS1.<student>.<version>.<signature> (QR_SIGNING_SECRET). Replacing a card bumps card_version.

Signed file links

Files download through short-lived signed links (FILE_SIGNING_SECRET, FILE_URL_TTL_SECONDS), so no token is needed in an <img>.

Postgres gotcha: user is a reserved word, so use the alias u in query builders and raw SQL.

7Auth and access

Sign-in (OTP)

POST /auth/otp/requestour user must be active · calls Central send-otp (registers on first use)
POST /auth/otp/verifyCentral verify-otp → our session
TokensJWT access + rotating refresh · Central tokens kept encrypted on the session
POST /auth/refreshrotates ours, refreshes Central · reuse → revoke · Central ended → SESSION_REVOKED
POST /auth/logoutends ours and Central's

AUTH_PROVIDER=central in real use. AUTH_PROVIDER=local gives the built-in OTP (test code 123456) for tests and demos. Deactivating a user revokes all sessions and push devices.

Roles

SUPER_ADMINADMINPRINCIPALAOTRANSPORT_INCHARGE HODTEACHERPARENTDRIVERATTENDANT

  • Permissions and role mapping live in modules/access/access.catalog.ts (PERMISSIONS, PERMISSION_CATALOG, ROLE_CATALOG). Add one there, then npm run seed.
  • Admin routes use @RequirePermissions(...); mobile routes use @RequireRoles(...).
  • A person can't be teaching staff (TEACHER/HOD) and bus crew (DRIVER/ATTENDANT) at the same time (roleConflict).
  • Proxy assignment is AO or super admin only.

8Notifications

notifications.dispatch({ template: 'STUDENT_ABSENT', audience: { user_ids: [41] }, data: { student: 'Arun' } })
1 · In-app rowalways; what the app lists
2 · Push (FCM)PUSH_DRIVER; to every registered device
3 · SMStemplate says always, or fallback and push did not reach a phone
  • Every attempt is a row in notifications (the outbox). The rows of one message share a batch_id.
  • Templates (English + Tamil) are in notification-templates.catalog.ts, loaded by the seed.
  • SMS route by SMS_DRIVER: log (outbox only), ping4sms (direct, needs DLT ids) or kafka (central Notification Service, topic NOTIFY_KAFKA_TOPIC, templateId = NOTIFY_TEMPLATE_PREFIX + code).
  • Jobs run on the in-process queue (QUEUE_DRIVER=memory) with retries. Queued jobs are lost on restart; Redis comes later behind the same switch.

12API conventions

Route families

auth/* me/* all apps · admin/* web · mobile/parent|teacher|driver/* Flutter · admin/fleet/* read-only bus status · files/* · integrations/* webhooks.

Two Swagger docs, one API

/api/docs/admin (web team) and /api/docs/mobile (Flutter team), split by path in swagger.ts. Both include auth, me, files and health.

Lists

Extend ListQueryDto (page, limit, search, sort, order) and use listQuery(). Response is { items, total, page, limit, total_pages, has_next }. Unknown sort → INVALID_SORT.

Errors

AppException.notFound('...', 'STUDENT_NOT_FOUND'). Codes are SCREAMING_SNAKE_CASE and stable, because clients switch on them.

Swagger on every endpoint

@ApiTags @ApiBearerAuth @ApiOperation @ApiEnvelope(Dto) @ApiErrors(...), with response DTO classes that carry examples.

Insight cards

Pages with counts get a separate GET .../insights endpoint.

15Testing and quality gates

Unit · npm test

46 spec files next to the code. No database needed. Pure *.logic.ts functions are covered first.

E2E · npm run test:e2e

Smoke tests against a migrated database.

Regression · web repo

npm run test:regression in Telamatics_web: API, browser and telematics suites.

Before every commit: npm run lint && npm test && npm run build must pass. When a client-visible contract changes, update docs/api-guide.md, Swagger and the web app's src/features/*/api.ts types together.
